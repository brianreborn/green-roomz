## What matters for a private LAN *behind* the FX4100

### Default posture (router mode)

- Device is a **cellular router** with Wi-Fi (up to 128 devices per datasheet/UG) and **2× 1 GbE WAN/LAN** ports (quickstart back-panel; userguide Ethernet tab).  
- Ports are labeled with default WAN or LAN; either port can be set WAN or LAN in **Network > Ethernet** (or Inseego Connect WAN Settings) — quickstart + userguide.  
- Default NAT: **Symmetric NAT (Strict)**; operator can select **Port-Restricted Cone** or **Full Cone** under Manage NAT Routing Type (`fx4100-userguide-en.txt`). More open NAT types are documented as less secure.

### Bridge vs IP Passthrough

- Docs do **not** describe a generic “bridge mode.” Closest cited feature is **IP Passthrough (IPPT)** (`inseego-ip-passthrough.html` / userguide LAN section):  
  - First device on the chosen interface gets the **IP assigned by the mobile network** — “one-to-one connection to a **host routing system**.”  
  - When IPPT is on: **only that one device** has internet; others lose access; **Wi-Fi (incl. Mesh) disabled**; **DMZ, Port Filtering, Port Forwarding** not available on the FX4100 UI (handled on the host).  
  - Cannot configure Ethernet ports as WAN while IPPT is on; Ethernet WAN connected blocks IPPT until that port is LAN or WAN priority lowered.  
- **Implication for private LAN:**  
  - Keep FX4100 in normal router/NAT mode and hang a downstream firewall/LAN → multi-device private LAN, double-NAT relative to cellular.  
  - Or enable IPPT to a single downstream router → that box owns the carrier IP (still subject to whatever address class the carrier assigns).

### CGNAT / inbound / tunnel punch-through (as stated in docs)

- The word **“CGNAT” does not appear** in the on-box userguide txt. Related facts that *do* appear:  
  - **Port Forwarding** and **DMZ** require a **static IP** on the line of service; contact the provider (`fx4100-userguide-en.txt`).  
  - Explicit note: *“Some mobile networks provide you with an IP address on their own network rather than an internet IP address. In this case, Port Forwarding cannot be used, because internet users cannot reach your IP address.”*  
  - Device Overview shows “internet IP address assigned to the router” — operator must verify whether that address is globally routable.  
- **Outbound** tunnels:  
  - **OpenVPN** client via admin **VPN tab** (upload provider configs); when OpenVPN is up, Port Filtering / Port Forwarding are ineffective (all traffic through tunnel).  
  - **IPSec** via **Inseego Connect** (not the local VPN tab); supports Anonymous Mode for endpoints without fixed static IP.  
  - Fortinet VPN note: connected devices using **IPv6 are incompatible**; disable IPv6 on the client for Fortinet.  
- **NAT type** (Symmetric vs PRC vs Full Cone) may affect peer/UDP punch behavior for apps that rely on NAT traversal — documented under Manage NAT Routing Type; no guarantee in docs that any setting yields public inbound reachability under carrier private addressing.

### Practical patterns for green-roomz / peer planning (doc-grounded only)

1. **Downstream private LAN (recommended reading path):** FX4100 as cellular edge (default NAT) → Ethernet LAN port → site firewall / green-room switch. Accept carrier-side NAT; use **outbound** VPN (OpenVPN on FX4100 or VPN on the downstream host) for peer connectivity.  
2. **IPPT to site router:** Pass carrier IP to one downstream router; run LAN/firewall/VPN there. Confirm carrier IP is public or static before expecting inbound.  
3. **Do not assume** port-forward / DMZ / inbound WireGuard listeners work without verifying static/public IP with T-Mobile and testing the assigned address class.

## Open questions for the operator

1. **Carrier address class:** Is the live FX4100 WAN/cellular IP a **public** address, **static**, or **carrier-private** (as warned in Port Forwarding notes)? Check Device Overview “internet IP” and ask T-Mobile for static IP if inbound is required.  
2. **Topology choice:** Stay in router/NAT mode with a downstream private LAN, or enable **IP Passthrough** to a single host router? (IPPT kills multi-client Wi-Fi on the FX4100.)  
3. **NAT type:** Leave Symmetric, or try PRC / Full Cone for specific peer apps — and re-test security exposure (`Manage NAT Routing Type`).  
4. **VPN path:** OpenVPN on the FX4100 admin VPN tab vs IPSec via Inseego Connect vs VPN solely on the downstream green-room host?  
5. **IPv6:** Needed for `Inseego.local`? Conflict with Fortinet (or other) VPN clients that require IPv6 off?  
6. **Ethernet roles:** Which of the two GbE ports is LAN to the private switch; is Ethernet WAN used for wired failover?  
7. **Firmware / unlock:** Carrier-approved firmware only; device “cannot be unlocked for use on other networks” (quickstart). Confirm approved image before experiments.  
8. **Inseego Connect:** Is the Manager add-on available for this T-Mobile unit if IPSec from Connect is desired?
